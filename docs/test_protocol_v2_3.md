# test 평가 고정 프로토콜 v2.3 (최종 제안 변경: 기대수익 순, 예산 무관)

공식 test 데이터를 받기 **전에** 작성했다. 커밋한 뒤 git 태그 `test-protocol-v2.3`을 붙인다.

v1, v2, v2.1, v2.2, v2.2.1의 계산은 그대로 두고 실행도 그대로 한다(`python scripts/40_test_evaluate_v2_2.py <test 파일>`). 이 문서는 **무엇을 최종 제안으로 볼지, 어느 판정으로 제안을 유지·철회할지**만 바꾼다. 계산 코드와 판정 정의는 바꾸지 않는다.

## 왜 개정하나

- v2.2는 "과제가 Sharpe 최대화를 요구한다"는 전제에서 포트폴리오 Sharpe를 주 지표로 두고 부도확률 낮은 순 80%를 골랐다.
- 2026-11-18 과제 공지를 다시 확인했다. **Sharpe는 필수 지표가 아니다.** 팀은 목적을 "Sharpe 최고 튜닝"이 아니라 "같은 양을 살 때 더 버는 선택"으로 정했다(decisions 43, 44).
- 그래서 주 제안을 처음 규칙서(v1)의 주 가설인 **기대수익 순위의 선별 가치(H2)** 로 되돌린다.

이미 본 것도 적는다. train에서 기대수익 순과 부도확률 순의 예산별 선별 가치와 Sharpe를 모두 봤다(30–42단계, `results/42_final_proposal_check.csv`). 바꾸는 근거는 과제 해석이지만, train 결과를 본 뒤의 결정이라는 사실은 남긴다.

## 1. 최종 제안 (고정)

매달 발행월의 36개월 대출을 기대수익 점수 s = (1−p)r − p·LGD − 국채 순으로 줄 세우고, 투자 예산만큼 위에서부터 산다. 남는 돈은 국채에 둔다. 승인비율은 정하지 않는다(예산 10–90% 전체에서 주장).

## 2. 주 판정 (v1 H2 그대로)

- **H2 선별 가치:** 기대수익 순위의 선별 곡선(승인비율 10–90%)의 무작위 대비 면적. 발행월 부트스트랩 95% 구간 하한 > 0.
- 정의와 계산은 v1(`docs/test_protocol.md` 4절, `scripts/15_test_evaluate.py`)과 같다.
- **통과하면 제안 유지, 실패하면 제안 철회.** 결과는 그대로 보고한다.

## 3. 보고만 하는 항목 (판정과 제안을 바꾸지 않음)

- 예산 10–90%별 기대수익 순의 선별 가치와 포트폴리오 Sharpe, 같은 예산 무작위 대비 차이(42단계 형식).
- v2.2의 H10(부도확률 낮은 순 80% − 무작위, Sharpe)과 H11–H13. 부도확률 낮은 순은 "흔들림을 가장 줄이려는 투자자"용 대안으로 보고한다.
- 허들 4단계(국채, +1%p, +2%p, BAA).

## 4. 해석 규칙

1. H2가 통과해도 "모든 예산에서 덜 흔들린다"고 쓰지 않는다. Sharpe는 예산별 구간으로만 말한다.
2. 보고 항목에서 다른 전략이 더 좋아도 제안을 바꾸지 않는다.
3. 큰 예산의 이점이 작다는 점(train 80%: +0.48%p)을 평균(+1.08%p)과 함께 쓴다.
