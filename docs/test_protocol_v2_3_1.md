# test 평가 고정 프로토콜 v2.3.1 (보완: 결과별 보고 문장, 실패 원인 점검표, 추가 후보 등록)

공식 test 데이터를 받기 **전에** 작성했다. 커밋한 뒤 git 태그 `test-protocol-v2.3.1`을 붙인다.

v2.3의 최종 제안, 주 판정(H2), 보고 항목, 해석 규칙은 **하나도 바꾸지 않는다.** 이 문서는 결과가 나온 뒤 무엇을 말할지와 실패하면 무엇을 점검할지를 미리 적어 둔다. 결과를 보고 주장을 고르지 않기 위해서다.

## 1. 결과별 보고 문장 (미리 고정)

| test 결과 | 제안 | 보고 문장 |
|---|---|---|
| H2 통과, H10 통과 | 유지 | "두 전략 모두 무작위보다 나았다. 더 벌기는 기대수익 순, 국채 기준으로 덜 흔들리기는 부도확률 순." 승인비율별 Sharpe 구간을 함께 보고한다 |
| H2 통과, H10 실패 | 유지 | "모델이 LC 가격이 놓친 대출을 찾았다. 위험한 20%를 거르는 것만으로는 덜 흔들리지 않았다." |
| H2 실패, H10 통과 | **철회** | "기대수익 순이 무작위보다 낫다고 말할 수 없었다. 부도확률 순은 무작위보다 덜 흔들렸다." H10은 발견으로 보고할 뿐, 부도확률 순을 새 제안으로 삼지 않는다(v2.3 해석 규칙 2) |
| 둘 다 실패 | **철회** | "이 test 기간에는 선별이 무작위보다 낫다고 말할 수 없었다." 해석 규칙 3에 따라 "LC 가격이 효율화되었다"를 대안 결론 후보로 쓴다 |

H2가 실패한 경우 표현을 구분한다.
- 구간이 0을 포함: "무작위보다 낫다고 말할 수 없었다."
- 구간 상한 < 0: "무작위보다 못했다."

## 2. 실패 원인 점검표 (미리 고정)

H2가 실패하면 아래를 순서대로 확인하고 **원인 가설로만** 보고한다. 원인 분석은 판정을 뒤집는 근거가 아니다. 특정 연도나 일부 승인비율만 골라 "그래도 이겼다"고 쓰지 않는다.

| 원인 후보 | test에서 확인할 것 |
|---|---|
| test가 다른 시기다(불경기 포함) | 발행연도 구성, 연도별 부도율이 train과 다른가 |
| 끝난 대출만 있어 부도가 과대 대표됐다 | 발행연도별 만기 도달 비율(0.9 미만 연도, 해석 규칙 1) |
| LC가 금리를 더 정확하게 매기게 됐다 | 등급 안 신호(H5)도 함께 약해졌나 |
| 모델의 위험 순서가 무너졌다 | p 10분위별 실제 부도율이 여전히 차례로 오르나(H1) |
| p의 크기나 LGD가 크게 어긋났다 | 예측 부도율과 실제 부도율, 그 시점 LGD와 test 부도 손실률 비교 |
| 그냥 운이다(표본이 작음) | 발행월 수, 구간의 폭 |

각 항목에서 확인된 것과 확인할 수 없던 것을 그대로 적고, 다음 데이터에서 시험할 질문으로 남긴다.

## 3. 추가 후보 등록 규칙

팀원이 다른 심사식을 test에서 함께 확인하고 싶으면 아래를 모두 지킨다.

1. **마감:** 2026-11-22까지 커밋하고 태그를 붙인다. test를 열기 전이다. 마감을 넘긴 식은 이번 test에서 빼고 다음 과제로 남긴다.
2. **문서에 적을 것:** 목표, 심사식, 승인비율이나 고르는 규칙, 판정 지표와 통과 기준, 실패 시 처리.
3. **채점 방식은 지금과 같게:** 발행월마다 자르기, 수수료 1%, 코호트 IRR, 같은 비율 무작위 10회, 6개월 블록 부트스트랩(B = 2000, 시드 2026).
4. **지위:** 보고만 하는 추가 후보다. test에서 더 좋게 나와도 주 제안과 주 판정을 바꾸지 않는다.
5. **중복 확인:** "부도확률 낮은 순 80%"는 이미 H10이므로 새로 등록하지 않는다.
6. **train 결과는 참고다.** 증거는 test 결과뿐이다.
