# test 평가 고정 프로토콜 (v2)

이 문서는 공식 test 데이터를 받기 **전에** 작성하고 커밋했다(git 태그 `test-protocol-v2`).
v1(`docs/test_protocol.md`, 태그 `test-protocol-v1`)은 그대로 두고 **전부 그대로 실행한다.** v2는 v1에 규칙·지표·가설을 **더하는** 문서다.
v1 이후 같은 train 구간에서 한 30~34단계 검증(포트폴리오 Sharpe, 절충 규칙, Sharpe 정의, 롱숏, 근본 가정 재점검)에서 나온 후보를 test 전에 고정하려는 것이다.
test 결과를 본 뒤에는 v1·v2 어느 것도 바꾸지 않는다. 벗어나야 하면 7절 '이탈 기록'에 남긴다.

실행: `python scripts/35_test_evaluate_v2.py <test 파일>` (v1의 표와 판정을 먼저 그대로 계산하고 v2를 덧붙인다)
예행연습: `python scripts/35_test_evaluate_v2.py --dry-run` (train의 30%를 가짜 test로 떼어 같은 코드를 돌림, 결과는 가설의 증거로 쓰지 않음)

## 1. v1에서 바뀌지 않는 것

점검(1절), 학습 데이터·시점 학습·모델·특성·LGD·비교 기준·수익률(2절), 규칙 R0~R3(3절), 가설 H1~H4(4절), 표 1~6(5절), 금지 사항(6절)은 v1과 같다.

## 2. v2에서 더하는 규칙 (승인비율 30%, 50% 두 곳에서 고정)

동점은 아주 작은 무작위 값으로 끊어 정확히 목표 비율만 승인한다(34단계에서 동점 때문에 실제 승인비율이 39.5%가 된 버그를 발견).

| 이름 | 규칙 | 역할 |
|---|---|---|
| V1 | 발행연도마다 기대수익 상위 q | 수익 축의 대표 |
| V2 | 발행연도마다 부도확률 하위 q | 안정성 축의 대표 |
| V3 | 발행연도·등급마다 최근 24개월 개설 계좌가 적은 q | 투명한 단순 규칙(34단계, 사후 선택이라 여기서 검증) |
| V4 | 발행연도·등급마다 부도확률 하위 q | 등급 구성을 무작위와 같게 둔 균형안 |
| V0 | 발행연도마다 무작위 q(10회 평균) | 기준선 |

## 3. v2에서 더하는 지표

- 수익: 승인 묶음 초과수익(발행월 IRR - 국채), 포트폴리오 초과수익(승인 금액 비중 × 그 값), 총 NPV(국채로 할인).
- 안정성: 발행월별 포트폴리오 Sharpe, 승인 대출 건별 Sharpe(과제식 숫자로 보고), 건별 Sharpe(거절 = 0), 하위 5% 평균.
  건별 지표의 대출 수익률은 받은 돈을 국채로 만기까지 재투자한 연수익률이다(대출 한 건의 IRR은 극단값이 커서 쓰지 않음).
- 등급 중립 롱숏: 발행월·등급마다 신호 상위 30% - 하위 30%의 묶음 IRR 차이(기대수익 점수, 부도확률, 계좌 개설, 무작위 위약). 6개월 이동 블록 부트스트랩 90% 구간.
- 등급별 발행월 초과수익과 Sharpe.
- 만기 도달 비율(발행연도 × 만기).

## 4. v2 가설과 지지 기준 (미리 정함, 주 표본 = test의 2013~16년 발행 36개월 종결 대출)

| 가설 | 지지 기준 |
|---|---|
| H5 등급 안 신호: 같은 등급 안에 돈이 되는 정보가 있다 | 기대수익 점수 등급 중립 롱숏의 90% 구간 하한 > 0 |
| H6 두 축: 수익은 기대수익 순, 안정성은 부도확률 순 | 승인 30%·50% 모두에서 V2 포트폴리오 Sharpe > V1 이고 V1 포트폴리오 초과수익 > V2 |
| H7 단순 규칙 | 승인 30%·50% 모두에서 V3가 V2보다 포트폴리오 Sharpe와 포트폴리오 초과수익이 모두 높다 |
| H8 Sharpe 정의 견고성 | 승인 30%에서 세 Sharpe 정의 모두 V2 > V1 |
| 점검 | 무작위 위약 롱숏의 90% 구간이 0을 포함(아니면 평가 코드부터 의심) |

## 5. 해석 규칙 (결과를 보기 전에 정함)

1. **종결 편향:** 만기 도달 비율이 0.9 미만인 발행연도·만기는 '종결 편향 가능' 표본으로 따로 보고하고 H5~H8의 근거로 쓰지 않는다. 그 표본에서 부도확률 순위가 이기면 26단계 시뮬레이션에 따라 '예상된 편향 방향'으로 보고하고 C6를 기각하지 않는다.
2. **만기별:** 60개월은 36개월과 등급 구도가 다르다(34단계 C). 60개월 결과는 보조로 따로 보고하고 36개월 결론과 섞지 않는다.
3. **효과가 사라지면:** H5가 지지되지 않으면 "등급 안 정보가 test 시기에는 가격에 반영되었다(LC 가격 효율화)"를 대안 결론으로 쓴다. 이는 연소득 신호가 해마다 사라진 것(34단계 A)과 같은 방향이다.
4. **크기보다 방향:** 효과 크기(약 1%p)는 기간에 따라 쉽게 달라지므로 '방향과 구간'으로 판정하고, 크기 비교는 참고로만 쓴다.
5. **H7은 사후 선택 규칙의 검증이다.** 지지되지 않으면 "train에서 신호를 보고 고른 규칙은 과대평가된다"를 정직하게 보고한다.

## 6. 하지 않는 것

v1 6절과 같다. 더해서: test를 본 뒤 승인비율(30%, 50%), 신호, 롱숏 비율(30%), 부트스트랩 블록 길이를 바꾸지 않는다.
